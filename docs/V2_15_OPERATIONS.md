## 第三新東京市の2.5D化

添付の構想図を参考に、芦ノ湖、箱根の山並み、道路・鉄道、高層市街地、地下空洞をSVGで追加しました。実測GISや公式の正確な建物位置ではありません。既存の4区画選択、施設健全性、迎撃、送電線、敵位置、EVA配置と監視への遷移を維持しています。

市街地は71棟の立体図形。区画の防護状態に連動してビルを収容し、健全性に応じて色を変えます。新しいアニメーションはこの状態変化を補間するもので、勝手に損傷や電力を変更しません。既存の施設画像・都市迎撃武器図はそのままです。

## 使徒迎撃と武器操作

使徒監視で対象を選び、「接近を受信」から交戦管制へ進みます。現在の都市損傷・資源・EVA状態を引き継ぎます。未処理の保安・MAGI保守がある場合は先に引き継ぐ必要があります。既存の匿名対象による通常訓練も残しています。

| 使徒 | 迎撃上の違い |
| --- | --- |
| 第3使徒サキエル | 接近、A.T.中和、コア攻撃。ナイフ・パレットで撃破可能 |
| 第4使徒シャムシェル | 中距離に光の鞭。接近中の左腕損傷をA.T.展開で軽減 |
| 第5使徒ラミエル | 高出力射界のため近接・通常弾を制限。外部給電、二段階充填、現ターン承認を経て陽電子狙撃。都市砲だけで倒せない |

外観・番号・基本的な特性はTV版を参考にし、HP・資源・反復出現・戦闘の数値は独自です。使徒図は新規のファンイラストで、既存の画像を差し替えていません。

交戦管制では、選択武器の図と名前、担当機、解析・距離・中和/充填・電力を同じ画面で確認できます。「次の準備」は実際の未成立条件に応じて、解析、接近、A.T.展開、中和、充填、補助送電、承認の一操作を案内します。未出撃なら従来のEVA起動・MAGI出撃承認へ移動します。準備を無条件に自動完了する機能ではありません。

条件成立時だけ、武器名付きの攻撃ボタンが有効になります。一回の命令は既存の保存・承認・資源消費ロジックを通り、命中表現は保存された損害に対応します。戦闘結果は6件まで保存。自動監視ONでは通常待機中の約60分以降に接近し、他の重大案件と重複しないようにしています。戦闘後は作戦を閉じて通常待機へ戻すか、手動で次の使徒を受信します。

## 保安捜査の操作

従来の3系統に、非正規中継器・盗聴回線、搬入物の不一致、偽警報による誘導を追加。自動発生する案件と「保安事例」で始める案件は現場捜査付きです。以前の「保安設定」の手順確認演習は、基本操作を学ぶ簡易形式として残しています。進行中の旧版案件もそのまま処理できます。

1. 案件を受領。搬入口で映像照会を実施します。
2. 記録に書かれた次の区画を選び、回線を追跡します。
3. 追跡先の最終区画へ巡回照会を依頼。次の30秒更新で現場報告が届きます。
4. 「区画制御」で、3記録の時系列に沿って3区画をタップし、経路を描きます。「3記録と照合」で一致を確認します。
5. MAGIへ経路照合を依頼し、結果到着後に解決方法を選びます。
6. 方針を記録し、冬月副司令への正式報告・受領を経て完了します。

照会枠は12。映像と回線は1、巡回は2を消費。間違った区画への照会は記録なしとなり、枠だけを消費します。未確認のまま経路を推測しても独立照合は成立しません。現場捜査の期限は24更新＝12分。旧版の簡易演習は従来の期限です。

解決方法は次の組合せです。

- **最終区画の一時保留**：地図上で対象の区画を選びます。2区画まで保留でき、搬入口・退避経路は閉鎖できません。正しい最終区画の保留を確認してから上申します。
- **記録保全・独立回線隔離**：文書・回線・偽指令の案件に使用。電力6を消費して問題の回線を分離し、報告へ進みます。
- **巡回担当の同行確認**：正規通行と独立確認できた入退館・搬入案件に使用。照会枠2を使い、1更新後に担当職員が確認します。
- **現場保安班への引継ぎ**：照会枠2を使い、2更新後に担当部署が証拠保全と現場対応を受領します。

証拠が少ない段階で不確定要素を上級へ上申する従来の経路も残します。担当職員が万能な司令官になるのではなく、照会、区画内の手順、担当部署への依頼を行う設計です。原作の特定人物を黒幕と断定したり、実際の侵入検知機能と表示したりしません。

## MAGIの新しい障害

冷却枝系統に加え、次の3種を実装しました。公式エピソードに存在する故障をそのまま再現したものではなく、三基の運用を題材とした独自の保守事例です。

| 障害 | 操作と成立条件 |
| --- | --- |
| 三基の時刻同期ずれ | 独立診断に表示された偏差へ、−8～+8 msの補正を各基に設定。すべて0 msなら照合成立 |
| 解析資料の整合性不一致 | 3複製を原本ROOT-215と照合。一致する複製元を指定。古いROOT-214は承認されない |
| 給電バスのノイズ | 診断で特定したバスを隔離し、健康な2系統の給電を維持 |

独立診断は1更新。入力・スイッチを変更しただけでは解決せず、独立照合と赤木リツコへの報告、次の更新での復旧承認が必要です。保守中は通常の審議・攻撃承認を保留し、停電・通信断・侵入・冷却対応中は診断を待機します。警報の全系統クリアで保守を消すことはできません。ホーム、MAGI、部署、人物通信、ネイティブウィジェットで同じ状態を参照します。

## 頻度と継続性

| 設定 | 保安の初回 / 解決後 | MAGI障害の初回 / 解決後 | 職員通信の最短間隔 |
| --- | --- | --- | --- |
| 通常勤務（既定） | 20分 / 30分 | 30分 / 45分 | 10分 |
| 低頻度 | 40分 / 60分 | 45分 / 75分 | 15分 |
| 集中演習 | 3分 / 5分 | 10分 / 15分 | 1.5分 |

通常勤務・低頻度では、待機中の冷却負荷が自然低下します。演算・侵入・戦闘による負荷は維持し、冷却異常の再発にも待機間隔を設けました。集中演習は従来に近い負荷上昇を残しています。日常点検の再受付は通常20分、低頻度30分、集中演習5分です。

職員通信・個人の自発通信・司令部の自動会話は、共通の間隔と同時処理制限を使います。起動直後の連続受信を抑え、職員通信は未読3件以上、入力中、非常時、非表示中には増やしません。緊急・状況に基づく連絡や、保留したユーザーとの会話の再開は別扱いです。手動で依頼する通信はこれらの自動受信制限と分けています。

`world.pacing`、`world.magiOps`、`world.angels`、保安案件の`fieldwork`は追加フィールドとして保存。未知の将来スキーマは保持して停止し、不正値の補完前には既存のバックアップ経路を使います。離席補完は最大6分相当のまま。再起動で大量の事件を作ったり、待っていた照会を二重実行したりしません。個人APIのKeychain保管・送信前記録・オフライン復帰も維持しています。

## Anime.jsと負荷

公式のAnime.js **4.5.0**を、MITライセンスとともにローカル同梱しました。実行時のCDN取得やnpmインストールは不要です。公式のエンジン・アニメーション実装を確認し、ビル収容、専用パネルの展開、確定した命中の短い表現へ適用しています。

Anime.js独自のRAFを無効化し、既存の共通描画エンジンに登録。最大6補間、単発100～800 ms、画面外・非表示・低モーション時は最終状態へ移して停止します。Canvasと同じ品質・描画頻度の予算内で進め、操作や保存の完了を演出待ちにしません。

実機のScriptable/WebKit、実FPS・電池・メモリ、実API・気象・位置情報は未検証です。ChromiumとScriptable APIモックの結果は[検証記録](VALIDATION.md)、取得できた資料と制約は[Web調査](V2_15_RESEARCH.md)を参照してください。
