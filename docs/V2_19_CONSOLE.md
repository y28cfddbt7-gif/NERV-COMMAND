# v2.19 統合管制コンソール

固定済みのEVA三機、全人物、携行・都市兵装、司令部、ジオフロント、使徒、v2.18街並みの画像とEVA描画CSSを保持する。画面の整理と共通ロジックの接続が変更対象。

## 戦闘の操作

ホームの戦闘管制から、接近目標を受領する。担当機を選び、機体準備とMAGIの実際の出撃審議を行う。承認後はMAP配置へ進み、中間・後方の六区画から射出位置、固定画像付きの兵装、外部給電の有無を決める。既存の進行中作戦は資源・損傷を保持して引き継ぐ。出撃済み機体を無料で修復・再装填しない。

配置後は同じ戦術盤で「移動」「戦闘・照準」「守備」を選ぶ。1手番は2AP。移動、解析、中和、充填、補助送電、狙撃姿勢、攻撃は各1AP。A.T.切替、照準、装備切替、給電確認はAP不要だが、各処理の電力・残弾・充填条件は引き続き適用する。守備または手番終了は残APを放棄して敵手番を解決する。

赤い予告区画は手番開始時に固定される。2APの途中で移動先に追従して書き換えない。中間の西・東の建物遮蔽とA.T.防御で実被害が減る。後方は近接使徒の射界外だが、ラミエルは後方も射界に含む。隣接移動、敵の射界、都市被害、機体損傷、弾数・電力を合わせて判断する。MAPの区画をタップ、またはドラッグで移動する。M→矢印→Enterでも操作可能。

攻撃モードでは兵装を選び、コア解析とA.T.中和などの条件を整え、実際にコアへ照準して発射する。A→矢印→Enterの照準も可能。照準外では命中せず、残弾・資源とAPを消費する。武器を替えると照準を取り直す。命中・ミス・敵攻撃の描画は保存成功後だけ発生する。ナイフとパレットは内部電源だけでも使用でき、陽電子射撃は外部給電と100%充填・都市電力40が必要。射撃ごとに現手番のMAGI実判定を行う。都市援護は初期保留のため、EVAによる勝利が独立して成立する。

敵手番は一度だけ解決し、内部電源10秒と個別行動分を消費する。思考中の攻撃担当機の電源は停止する従来の手番ルールを維持。演出速度は世界の時間を変えない。停電・通信断・MAGI/保安の保留には原因画面への明示的なリンクを表示する。

戦闘の公開ナビゲーションは「発進承認」「MAP・戦闘」「作戦記録」の3つ。MAP配置は工程専用の独立URL `#battle/deploy`。旧の戦闘URLは統合経路へ転送する。施設の配備・修理と防衛方針、兵装資料・拡大、職員の指揮照会は維持し、そこから別の戦闘方式を始めない。

## MAGIシステム

公開ナビゲーションを「三基管制」「処理履歴」「演習・設定」の3つに集約。`#magi/main` に三人格、独立選択可能な三基、共通接続、実測定結果、現在の操作盤を表示する。旧の保守・侵入・666等のURLと冷却異常の業務URLはこの画面へ転送する。通常時は出撃対象機の審議と現手番の実戦術承認を選べる。出撃否決には実際の理由を表示し、侵入・保守保留中の通常承認は拒否する。

異常は外部分散侵入→自己進化型侵食→三種の保守→冷却の順で現在の実案件から表示する。既存保存で複数案件が重なっていても下位の案件を消去しない。

| 状況 | 操作・判断 | 復旧条件 |
|---|---|---|
| 時刻同期 | 三基を独立測定、偏差に応じて補正スライダーを調整 | 三基すべて0ms、独立照合と技術部承認 |
| 給電バス | 三入力と冗長出力A/B・保守のパッチ接続 | 異常バスだけ切離し、健全二系統は別々の給電経路を維持 |
| 資料整合性 | 三複製の署名を測定・比較して複製元を選択 | 全複製の照合、署名原本と一致する複製元、技術部承認 |
| 冷却枝系統 | 異常枝を保守へ、健全な二流路を分離、流量を配分 | 各35以上・合計100以内、独立診断と技術部承認 |
| 自己進化型侵食 | 攻撃経路の隔離、AND署名マスク、対抗命令列の構築 | 正常署名を通す複合検出、独立したCASPER、境界固定→進化観測→終端誘導 |
| 外部侵入・666 | 別々のコアで独立経路解析、経路隔離、演算配分 | 合計30・各基の必要枠を確保。遮断ごとに攻撃源が移動し、再測定・再配線・最大圧コアの選択を3周期実施 |

パッチ盤は入力→出力へドラッグする。詳細欄の選択操作でも同じ接続を設定できる。単に「次へ」を押しても測定不足・誤接続・誤補正・誤署名・演算不足では進行しない。測定値は実案件に由来する。正常な三基に偽警報や意味のない乱数を流さない。30秒更新の独立診断・部署承認は従来の世界エンジンが担当し、操作しただけで時間を飛ばさない。

## 構成と保護

- `v219-console-engine.js`: `operatorConsole.schema=1`。AP/工程/配置/操作モード、測定・配線・署名・命令列・演算配分、24件までの操作履歴。既存の `evaCombat` / `world.magiOps` / `magi.intrusion` / `magi.externalDefense` が実行結果の唯一の状態。
- `v217-tactical-engine.js` と `v210-operations.js` は同期適用処理を抽出した。既存公開APIは同じ処理を使い、新AP制御も一つの保存トランザクション内で呼ぶ。二重保存や先行するAP消費は行わない。
- `v219-battle-ui.js` / `v219-magi-ui.js` / `v219-navigation.js`: 既存DOMと描画を再利用し、公開入口と操作を統合。旧パネルは既存描画・保存・互換API用にマウントを保持し、公開タブは整理する。
- 保存前バックアップ、排他、失敗時の全状態ロールバックを再利用。未知の保存項目を保持し、新しいコンソールスキーマ・不正座標・破損記録は上書きせず停止する。過去のハッシュfixtureは書き換えない。
- 固定画像、共有の街並みデコード、透明Three.js、既存Canvas命中演出、Anime.jsの制限を保持。新しい無制限タイマー・RAF・外部CDNは追加しない。処理中のCSS演出は非表示・低モーションで停止。

## 調査と検証の限界

[OpenXcom公式ソース](https://github.com/OpenXcom/OpenXcom/blob/master/src/Battlescape/ProjectileFlyBState.cpp) をHTTPSで取得し、行動資源・装備条件・射撃照準と実行可否の事前検査を確認した。v2.19はそれを設計の参考とし、GPLコードをコピーしていない。2AP、予告射界、配線・署名課題などの値と手順はこのアプリの独自ルール。

Into the Breachの公式紹介・Steamページ、エヴァ公式サイト、EvaGeeksのMAGI記事も検索・取得を試みたが、公式/Steamは403、EvaGeeksは526。Bing/Google検索は取得できたが、MAGI固有の構造を確かめられる本文は得られなかった。読めなかった資料を精査済みとは扱わず、既存のTV系列の三人格・CASPERの未侵食領域などの設定を維持する。作品映像をピクセル単位で再現したもの、公式の対処手順としては表記しない。

検証結果は `docs/VALIDATION.md` と `handoff/V219_VALIDATION_LOG.txt`。物理iPhoneのScriptable/WebKit・GPU負荷・FPS・電池消費・実APIは未検証。Chromiumの操作とnativeモックを実機結果として扱わない。導入は小型STARTERを一度コピーし、画像を含む大容量本体はチェックサム付き取得とローカルキャッシュを使用する。
