# v2.11 職員業務シミュレーション：第一段階

基準はv2.10 `92a7767`、その親はユーザー指定の`07f2242`を継承したv2.9です。既存機能を一から置き換えず、保護された53ファイルとEVA三機・パイロット顔を保持して拡張します。

## 最初に確認する場所

ホームの先頭に「当直・司令部」を置きました。管制職員業務、NERV司令部、司令部職員との会話、666プロテクトへ直接移動できます。従来の気象・EVA・都市・戦術等は「各管制・訓練」に保持。ホームはボタンと発令中の警報のままで、長い全機能一覧へ戻しません。

- **損傷表示**：NERV司令部→「地上・本部の損傷表示」。区画HPと地上・地下の眺望が連動。健全なら「損傷なし」と明記し、見せるための架空の被害は発生させません。
- **5人の会話**：ホーム→「司令部職員と会話」。ミサト・リツコ・マヤ・日向・青葉の顔を選び「状況報告を受ける」。館内通信ON時は初回入室・未受信の職員選択でも報告を受信。冷却異常があれば、その案件に応じた報告になります。
- **666防御**：ホーム→「666プロテクト」→外部ハッキング訓練を開始→「666防御指示」。解析2回→構築→維持3回が基本。既存の限られた演算資源・対象コア隔離・再起動の危険・成功/失敗は維持。
- **投影**：発令所には状態に応じたWebGL走査・格子、666表示には侵入圧・防壁の状態を反映した六角投影を追加。非対応時は軽量背景、低モーション時は静止。投影の状態を発令所のキャプションにも表示します。

## 第一段階で実装した範囲

1. 共通世界状態エンジン：`S.world`の設備負荷・業務・異常・部署通信・時刻を管理。
2. 保存復元：従来の保存キーを維持し、追加前の控え、直前の正常保存、破損の退避、未知項目の保持を実装。
3. 日常業務1種類：MAGI冷却系統点検。
4. 因果的な異常1種類：冷却負荷の蓄積による枝系統流量異常。
5. 対応による実状態の変更：枝系統隔離、通常審議保留、診断、技術部承認による再接続。
6. ホームとMAGIへの反映：同じ状態から当直・部署・MAGIの表示と操作条件を計算。
7. 業務・案件・部署通信・対応履歴：ページ分割して保存・表示。

### 担当業務の操作

管制職員業務→担当業務で、**受領→系統表示を確認→MAGIへ解析依頼→結果待ち→技術部へ報告**と進めます。解析は次の30秒更新で完了。報告後は技術部が予防整備を実施し、冷却負荷が軽減します。次の点検は完了後5分相当以降に受付。保留した業務は再受領して再開できます。

報告はスコア獲得ではなく、部署への引継ぎとして記録。経験値・勝利数を追加しません。管制技術補助C-3の権限は、点検・解析依頼・許可された枝系統隔離・報告に限定しています。C-3は本端末独自の業務区分で、原作の階級ではありません。

### 自律更新と異常対応

画面が表示されている間は、操作しなくても30秒単位で設備状態が更新されます。通常稼働の負荷増加は2/周期、MAGI解析・外部侵入対処中は6/周期、作戦中は3/周期。主電源停止中は負荷を増やしません。これらは原作の設備仕様ではなく、因果関係を確認するための独自模擬ルールです。

負荷70%で流量異常を起票し、90%または枝系統隔離中は通常MAGI審議を保留します。同種の未解決案件を重複発生させません。初期負荷20%から放置すれば通常稼働で約12.5分相当で初回異常。点検報告による予防整備で時期は変わります。単にランダムな警報を表示する方式ではありません。

**案件を受領→許可された枝系統を隔離→独立診断を技術部へ依頼→結果を赤木リツコへ報告→技術部が復旧承認**。診断と復旧承認はそれぞれ次の30秒更新で進行。職員が勝手に全系統を復旧する操作はありません。案件の警報確認も、全復旧ではなく担当画面へ誘導します。復旧後は出撃・迎撃承認を改めて申請します。

枝系統の異常は適応侵食や外部ハッキングと別の案件です。666を万能な冷却故障修復として扱いません。MAGI侵入中は新しい解析・診断依頼を保留し、侵入対処を優先します。

### 離席と復元

非表示中はタイマー更新を止め、復帰時に保存時刻から最大12周期（6分）だけ再計算。超過時間は履歴に保留として記録し、次の復帰で同じ時間を再処理しません。端末時刻が戻った場合も、基準時刻を補正して二重処理を防ぎます。離席中に自動で都市を破壊したり、パイロットを負傷させたりする処理はありません。

解析中・異常対応中・承認待ちの途中状態を保存。履歴48件、部署通信16件、業務12件、案件12件に上限を設け、表示は4件/3件ずつページ送り。破損した項目や重複を補完する際は元の状態を別保存し、他の既存機能の記録を消しません。将来版の世界スキーマは書き換えず、職員業務の引継ぎを停止します。

全体JSONが壊れた場合は原文を退避し、直前の正常保存があればその控えから復元。控えがなければ元データを保持したうえで初期状態で開いたことを通知。退避に失敗した場合は、元のファイルを上書きしません。失われた最新部分を必ず復元できるという意味ではありません。

## 構造と既存機能との境界

| 要素 | 実装 |
| --- | --- |
| 世界状態・遷移 | `src/browser/staff-world.js`。時刻・状態入力から業務/異常/通信を更新 |
| 画面・制御 | `src/browser/world-workflow.js`。バックアップ・保存・失敗時の巻戻し、MAGIへの接続 |
| 初期保存の保護 | `state-safeguard.js`を旧読込前、`persistence-guard.js`を旧ブリッジ後に追加 |
| 既存の機体・都市・電源・MAGI | 複製せず既存`S`から投影。独立した数値を画面ごとに保存しない |
| 役割 | 新しい職員業務のコマンドは許可リストで制限。整備・再接続の決定主体は技術部 |
| 保存 | 既存キー/JSON名を維持。追加は`world`、正常保存の控えと退避ファイル |
| 導入 | 小さな`STARTER.js`からSHA-256で固定した本体を取得・保存。画像は元バイトを維持 |

既存の直接戦闘・出撃・上位承認・全体クリアは訓練機能として保持しています。アプリ全域の役職別アクセス制御、複数部署の自律判断、実戦をNPCが進める仕組みは第一段階の範囲外です。新職員業務の権限制限だけで、全旧画面の統一権限制御まで実装済みとは扱いません。
