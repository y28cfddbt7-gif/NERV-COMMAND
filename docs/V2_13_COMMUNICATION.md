# v2.13 通信システム

v2.12 `b24dad39f90e3d4b1ce9863431163792b8c1015e`から継続。従来の8人の個別トーク、固定画像、戦闘・当直・MAGI・気象・6ウィジェットを保持しています。主画面は11、区画は68です。

## 使い方

ホーム → メッセージ → パイロット / 司令部 → 相手を選択します。選択式の4話題と160文字の自由入力を併用できます。人物はシンジ・惣流アスカ・レイ・ミサト・リツコ・マヤ・日向・青葉・ゲンドウ・冬月の10人。従来8人の顔を維持し、新規2人は「司令 / 副司令」の識別章です。

- 「MAGIの解析結果は？」などは、人物の担当と実際の解析状況を照合して返答します。
- 「その続き」「前の依頼の続き」は相手ごとの話題・依頼を参照します。
- 「私はギターが好き」のように明示した好みは、その相手との会話だけに記録します。「覚えてる？」で振り返れます。
- 同じ質問を続けると再確認として応答し、直近の表現を避けます。知らない内容は確認を求めます。
- 「またね」で区切り、後から再開できます。警戒・戦闘・非常時の雑談は保留します。
- 「解析を依頼して」などは**未実行の提案**を表示します。ボタンで担当画面に移動し、既存の権限・要件・確認手順で処理します。会話だけで発令・資源獲得・業務完了にはなりません。

「職員情報」と「通信記憶」を独立区画に分けました。履歴は4件ずつ閲覧でき、長文は履歴領域内でスクロールします。トークURLは`#messages/thread/maya`など相手も保持します。戻る・再読込を維持します。

## 改善した仕組み

旧処理は話題ごとに2行を交互選択し、送信時に返答を確定していました。文脈は交換回数だけで、自由入力も少数キーワードから4話題に振り分けるだけでした。

新処理は `v213-personas.js` の人格・職務・知識範囲と、`v213-conversation.js` の話題判定・記憶・状態照合を組み合わせます。通常・警戒・戦闘・非常を区別し、**受信時の状態**から返答を作ります。EVA状態・同期率、冷却負荷、解析段階、異常、正式な点検報告、作戦結果を実データから参照します。私的に「完了した」と伝えても正式記録は変えません。

返答はオフラインのルールと独自の会話文を組み立てます。生成AIのような幅広い意味理解はありません。人物の趣味と無関係な具体的知識を創作して回答する仕組みではありません。人格の細かな心理描写・親しさの変化は本アプリの解釈です。

## 自発通信

館内通信ON時、解析完了・冷却異常・MAGI侵入・戦闘開始・機体整備中・保留した会話の再開・通常時の連絡を、実際の条件から選びます。受信のために画面を切り替えず、音やモーダルも出さず、未読件数で通知します。

異常・侵入を最優先、作戦・解析を次、雑談を最後に判定します。全体30秒（非常）/90秒（その他）、相手ごと60秒（非常）/5分（その他）の間隔と直近32件の発生キーで反復を抑えます。通常連絡の判定は90〜180秒間隔。重要連絡は既存の5秒周期（返答待ち時1秒）で確認します。警戒以上では雑談を送りません。入力中・非表示中は自発通信を止めます。パイロット自動通信OFFはパイロットを対象から外し、館内通信OFFは全員を止めます。

## 保存と負荷

`S.personalMessages.schema=1`を保ち、各スレッドに`memory.schema=1`、共通に`automation.schema=1`を追加する互換拡張です。既存の未知フィールドを保持し、移行・破損補完の前に従来の通信専用バックアップ / 隔離コピーを保存します。未来版の通信・記憶・自動通信スキーマは上書きせず停止します。

人物ごとの最新24メッセージ、直近8質問/表現、重要な依頼・出来事6件、明示した好み3件に制限。返信待ちは相手ごと1件。旧版の確定済み返信も引き継ぎ、送信IDによって二重受信を防ぎます。保存失敗時は会話と記憶をまとめて巻き戻します。入力中の返信は入力本文・フォーカスを維持します。

既存の単一通信タイマーを再利用し、隠れている間は停止します。接続・受信のCSS演出も非表示・低モーション・演出OFFで停止します。画像の再圧縮・巨大データの追加はありません。約13 KBのSTARTERを貼る方式を継続します。

## 外部AI：第三段階の境界

今回は第一・第二段階のオフライン機能を実装しました。**API設定・外部送信・生成AIモードは未実装**です。キーは要求せず、外部の会話サービスへ本文を送信しません。

`NERV_MESSAGES.context(id)`は人格、相手に公開可能な状態、本人との最新12メッセージ、記憶の分離コピーを返します。パイロットには自機のみ、技術職には担当点検を渡し、別の相手の履歴は含めません。`validateSuggestion`は320文字以内の文章と許可された4種類の画面確認提案のみを検証し、状態変更・任意コード・不明な操作を拒否します。この境界は拡張用であり、既存の実行APIへ自動接続していません。

第三段階の実装順序：

1. Scriptableネイティブ設定でKeychainへ秘密を保存。WebView / ソース / 保存JSON / ログへキーを渡さない。
2. 外部送信を明示的にONにした場合だけ、限定されたHTTPSエンドポイントへ上記コンテキストを送る。現在の橋を長時間占有しない非同期経路を追加する。
3. 時間制限・同時実行上限・世界状態が変わった場合の再照合・応答検証を実装。未設定・障害・不正応答では現在のオフライン処理へ戻す。
4. 許可済み提案も担当画面へ誘導し、人が既存の確認手順で実行する。AIに内部状態の更新権限を渡さない。
5. APIモック、秘密の非露出、タイムアウト、保存競合、実機での設定・復帰を検証する。
